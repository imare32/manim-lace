## 1. 现象

用户在两块肋条面板上各框出一处（world ≈ `(+1.03, -0.80)`），放大 18 倍确认（图：`media/spot_tight.png`）：

| 面板 | 现象 |
|---|---|
| boolean | 紫色（Over）丝带被一条**多余的斜向黑边横切**，看起来像被"截断"，即用户说的"Over 多了一条边截断" |
| arrangement | 一条**短横线**（约 0.058 世界单位）从右侧**戳进**紫色丝带内部，即"描边戳进丝带" |

两块面板在同一位置的**填充**完全一致（同样的紫/蓝/靛三色与纸缝），差别只在**描边**上，所以这是描边层的问题，不是填充覆盖问题。

## 2. 已量化的定位

判据"某条被描边的区域外边**严格落在自己丝带内部**、且**不在任何其它丝带边界上**"（容差 1e-4）：

- boolean 面板 **118 条**，arrangement 同量级；
- 这 118 条**全部属于 `P0002`**（level-2 那条 21 点自交环）的区域；`P0000`/`P0001` 为 **0**；
- 全卡 **240 条分段切口弦也全属于 P0002**；P0002 共 120 段、120 个分段边界弧、20 个自交。

逐条追查（`P0002#0.region0` 的 `(+1.0554,-0.8890)->(+1.0374,-0.8337)` 等 4 条）：

- 它们落在 **arc 相邻的两段**（strip 81 与 82，共享 arc `49.9221`）的**可见带边界**上，距边界 `3e-6 ~ 2e-5`；
- 但它们**不在整条路径带的边界上**（离中心线 0.028~0.055，小于 `offset=0.08`）；
- `_cut_lines` 用 `arc ± probe` 推出来的弦与它们**差 17.97°**（正好是玫瑰线相邻两点方向的夹角 18°），最长平行度也对不上。

**结论**：`mark_flush_edges` 依赖的合成弦在这里描述不了真实接缝，于是这些边被当成轮廓描了出来。而它们既不是整带轮廓、也不在别的丝带轮廓上——那正是"丝带中间多出一条线"的签名。

> ⚠️ 这个判据**过度计数**：它把自交的**切口边（notch）**也算了进来——自交的两遍是同一条路径，
> "别的丝带边界"是空集，notch 自然"不在别的丝带边界上"。notch 是必须描的编织线（见 §3.2），
> 118 条里绝大部分是 notch，不是缺陷。

## 3.0 真正的根因：两个后端在自交处对"谁压谁"的判断不一致

用户看到的两条线，是**同一个 weave 分歧的两种表现**。以自交 `X0050`（点 `(+1.1135, -0.809)`，
`s_a=0.5257` 在水平那一遍上，`s_b=49.9221` 在陡的那一遍上，`sin θ=0.9511`）为例：

- assignment 说 `under_side="a"` → **水平那一遍在下**。stroke 面板确认（水平遍在 arc 0.5257
  附近有缺口，`P0002.piece1` 从 0.6122 起），boolean 面板也照此把水平遍切开（strip 0/1 带 notch）。
- arrangement 后端把透镜的归属按**路径**命名（`over_path_of`）——自交的两遍是同一条路径，
  只能按 node id 兜底（`min(distinct, key=(-layers, node))`）。X0050 上覆盖透镜的分段有水平带的
  `P0002#0`（arc 段 `[0.5257, 1.9021]`）和陡带的分段，id 小者胜 → 透镜归了**被压的水平遍**，
  weave 就地反转。
- 反转的后果正是用户框出的两条线：
  - boolean 照 assignment 切开水平遍，描出该交叉的第二条 notch 线 **L′**
    （`(+1.1716, -0.729) → (+1.2236, -0.889)`，沿陡带 +normal 侧，长 0.168）——arrangement 不描；
  - arrangement 把透镜给了水平遍，水平带"整条不断"，反而切开陡遍，于是描出沿水平带下边、
    **落在透镜内部**的一小段（`P0002#26.region1` edge 3，`(+1.2236, -0.889) → (+1.1135, -0.889)`，
    长 0.110）——一条画在丝带中间的黑线。

**修法**：自交没有第二条路径可命名，就按**分段**命名压住的那一遍——
`over_sections_of[crossing_id] = _StripBuilder.adjacent(sections[path], over_arc, …)` 的 strip id，
透镜面优先归它们；只有这些分段一个都不覆盖该面时，才回退到原来的路径序。这样两个后端
（以及 stroke 参考通道）在自交处切的是同一条丝带。

## 3. 试过、且已被否掉的两个修法（不要再走一遍）

1. **"lens 边界落在被压那一遍自己分段边界上的部分记为接缝"**
   （想法：洞/切口边界里，属于被压丝带自己侧边的那半段是被盖住的侧边，不该描）
   实测：在这张卡上**一条也没匹配到**（`lens.boundary ∩ 分段边界`为空），画面零变化 → 否掉。

2. **"严格落在自己丝带内部、且不在其它丝带边界上 → 不描"**
   实测：boolean 面板的 118 条确实全部清零（`inside own` 计数 118 → 0），但被既有测试当场否掉：

   ```
   tests/test_regions.py::test_a_self_crossing_marks_the_section_cuts_as_seams_not_the_notches
   assert 0.1 == 0.2 ± 1.0e-09
   ```

   该测试明确要求：**自交的切口边（notch）必须留在 `flush_edges` 之外**——注释原话是
   "marking them is what drew ticks across the ribbon"。单路径图上"别的丝带"为空集，
   这条规则会把切口边一并吞掉，等于抹掉自交处的编织关系 → 否掉。

**由此确立的约束**：只用**局部带几何**无法区分"分段接缝"（不描）与"自交切口边"（要描），
这一点仓库文档 `docs/SELF_CROSSING_OUTLINE_TICKS.md` §3(b) 早已写明。修法必须引入
"**哪一遍是哪一遍**"的信息。

## 4. 下一步方向

（本节的两个方向都是在 **flush 层** 补救；真正生效的是 §3.0 的**透镜归属层**修法。保留备查。）

1. **按弧长归属判定**：`_sections_around(group, arc, reach, path)` 已经能在自交分支给出
   `under_sections` / `over_sections`。把"接缝"定义为**端帽弧长相邻的两段**之间的边界、
   把"切口"定义为**同一个交叉的两遍**之间的边界，据此生成 flush 集合，而不是靠 `arc ± probe` 的合成弦。
   注意：`_section_seam_chords`（本仓库曾试写过一版：取相邻两段可见带的共享边界）在这张卡上
   也未生效——因为相邻两段的可见带是**相互重叠**的，共享边界退化成点，真正分界的地方是
   "一段的边界落在另一段内部"的那条线，需要专门取。
2. **或者从后处理入手**：在 `mark_flush_edges` 之外，对 P0002 这类自交路径的描边 run 做一次
   "同色两侧 + 不在任何带边界上"的过滤——但要同时用 `flush` 集合保住切口边（正是 §3.2 失败的地方）。

## 7. 第二轮：用户反馈"还没有真正修复好"之后的复测与三个新根因

第一轮修完，用户核对原卡片图片认为"好像修好了"，但要求多画几个玫瑰线例子确认。
复测方法（`benchmarks/weave_audit.py`，图片 `media/verify_*.png`，红色 = 缺陷签名）：

- **配置**：24 个（n = 5…13 × PA/PO/PR/CA/CR × offset 0.05…0.12，含单层与两层合并），
  每个配置渲染 boolean 与 arrangement 两个后端，共 48 个组合。
- **判据**（§2 的缺陷签名，避免 §2 过度计数的问题）：被描边的外边，两侧探针都落在
  **某个**已绘区域内（逐区域判定，不对并集判定——见下）、两侧最上层路径相同、
  且不在任何透镜边界上。另测反向签名"标了 flush 却在最外轮廓上"（缺轮廓）。

结果：原卡片（n = 10 PA L1+2 o0.08）两个后端确实是 0，但另外 6 个配置命中。三个根因：

1. **`mark_flush_edges` 的 flush 索引错位**（`src/manim_lace/render/regions.py`）。
   环按判定结果重建，却只在**点数变化时**才替换。一条边被 split（多一个顶点）的同时
   另一对近乎共线的边被合并（少一个顶点），两者抵消、点数不变 → 原环留着，却穿着
   寻址另一个环的 flush 索引。实测 `n = 7` CA L2 o0.10 boolean 的 `P0000#14.region0`：
   边 1 被切成"可见+隐藏+隐藏"，环却保留整条边 → 0.111 的线横在丝带中间；边 3
   （真实外轮廓）反被隐藏。修法：逐点比较，joined 环与原环只要不同就替换；合并后
   不足 3 段的环是零面积细条，保留原环并按"全隐藏或全不隐藏"处理；整条边一个判定的
   片段直接沿用环上原来的点（什么都没发生的环逐字节不变）。

2. **arrangement 后端按节点合面时 GEOS 并集丢面**（`render/arrangement.py` 新增
   `_node_geometry`）。一次性 `unary_union(faces)` 会**静默丢掉只与邻面共边的面**，
   且谁活下来取决于操作数顺序。实测 `n = 7` CA L2：并集丢了一个 2.3e-3 的面，画出来
   是丝带上的洞（`gap.union(f1)` 保留、`f1.union(gap)` 丢弃、两种顺序的 `unary_union`
   都丢）。修法：平面剖分的面两两不重叠，面积和是精确值；并集面积对不上就保留这些面
   本身，让渲染器把它们作为各自独立的区域画出（共享边同色内部，照常标 flush）。
   `painted_area` 同理改为精确求和。

3. **`_drop_folds` 一批多删，把真实薄楔形删掉**（`render/regions.py`）。两刀切弦在丝带
   侧边上相交时，楔尖会留下同一个点的几个副本（只差最后几位，布尔运算的噪声）；每个副本
   单独看都像"零面积折返"，一遍全删 → 环真正转弯的顶点消失，整个楔形（2.8e-3）被切掉。
   实测 `n = 11` CR L2 o0.07 boolean 的 `P0000#20`。修法：一遍只删一个折返，删完重判
   （文档字符串一向如此声称，只是代码没做到）；最后一个副本对照环的真实转角，保留。

附带修掉同一族问题的两处（`CHANGELOG.md` 有完整记录）：

- **大面积并集丢面 + 内部判定依赖并集**：`n = 13` CA L2 o0.05 上 158 个有效面有 40 个
  未被并集覆盖、面积少 5e-2（各种操作数顺序都一样）。面积记账（`painted_area` /
  `union_area` / `hidden_area`）改为逐部分求并并验证"每个部分都被覆盖"（有损并集是
  真并集的下界，验证过的 Attempt 即精确值），误报的 `REGION-AREA-MISMATCH` 随之消失；
  `mark_flush_edges` 的内部判定改为**逐区域**提问，不再问并集。
- 复测脚本自身的并集假阳性（零面积区域、1e-16 长的噪声边）已在脚本里排除。

**复测结果**：48 个配置×后端组合，缺陷签名全部 **0**；唯一残留是 `n = 5` CA 上一条
1.6e-7 世界单位长的细条边（卡片尺度下不可见）与若干零面积区域。原投诉卡片的面数/诊断
与修复前一致（159 / 90 可见面），无回归。全量 `pytest -q` → 384 passed，`ruff check` 干净。

## 9. 第三轮：用户指出 CA7 卡上"描边戳进丝带"——缺口在丝带中间断掉

**现象**（用户 crop 的 boolean 面板）：一条描边从交叉处斜穿丝带，在丝带内部**断掉**，
没有走到丝带的另一侧边缘。

**定位过程**（`media/probe_ca7_*.py`）：

1. 先按 §2 的缺陷签名复查：48 组仍是 0——说明这不是"多画的线"，而是**少画的线**，原签名看不见。
2. 把渲染器真正发出的描边（每个区域环上非 `flush` 的边）与每条透镜边做一维区间比较：
   `X0010`（点 (+1.0, 0.0)，两条长臂以 25.7° 相交的自交）的透镜边 0 只画了 **81%**，
   缺最后 0.088；同一条边在 arrangement 后端是 **100%**。
3. 逐段追这条边：它被分段切成三块——`P0000#34` 的两块（0.0228 + 0.3498）**被描边**，
   最后一块（0.0883）落在**后画的 over 侧区域 `P0000#62`** 环上，被判成"自己的带边被覆盖"
   而**隐藏**。
4. 为什么 under 侧不carry这块：`P0000#34` 是分段（窗口）strip，它到窗口帽
   `(0.9803,0.3633)→(1.0218,0.3538)` 就结束了，窗口外的 under 材料属于"两块窗口之间的长条"，
   那里没被切——所以缺口末段只在 over 侧区域的环上。

**根因一**（`is_hidden` 的判定顺序）：`band.boundary`（"自己带边、被别的覆盖"）测试跑在
`weave_geometry`（透镜边界=编织缺口）测试**之前**。而 over 那条 pass 自己的侧边横穿 under 那条
pass 时，**它本身就是缺口**——被前一个测试吞掉，于是 where under 侧不 carry 时没人画。
修法：缺口测试提前，并加上"可见面"条件——`outer != inner`（两侧最上层区域不同）且本区域是其中
一侧的可见面时描边；若后画的第三层股线两面都盖住，缺口确实藏在下面（描边由那层负责，线不该
出现在它内部）；若两侧同属本区域，则线在它自己的填充里，照旧隐藏。`topmost` 顺手改成返回
区域索引（顺带把每点的包含查询从 4 次降到 2 次）。

**根因二**（boolean 后端记录了什么当 weave）：它把**被扣除的透镜**边界记进 weave。那个透镜是被
分段窗口裁剪过的（`_self_crossing_lens` 用*当前可见*分段求交，这是刻意的局部化），所以它的边界
里既有真实缺口、也有**分段帽（接缝）**，还**到不了真实缺口的末端**。接缝被当成缺口会把帽子当
缺口描，缺口末端反而认不出来。修法：改记**两条臂带求交**的边界——也就是 arrangement 后端本来就
用的那个透镜。`_arm_strip` 从 `arrangement.py` 移到 `regions.py`（两个后端都用）。

**复测方法升级**（`benchmarks/weave_audit.py` 新增 `notch gaps` 栏）：把每条记录的透镜边与
区域实际发出的描边做一维区间比较；未被覆盖、**且两侧可见归属确实不同**的区间才算缺口（两侧
同属一个区域时，在那里描边反而是"丝带中间的线"，不算）。升级前该栏在 22 组上报假缺口（把接缝
帽当成缺口线等），升级后 48 组里 46 组为 0。

**残留（诚实降级，更新后）**：显式 `outline_edges` 层把 `n5 CA L2 o12` 的 boolean 缺口从
6 处/1.44 降到 **0**；`n5 PO L2 o12` 从 5 处/0.835 降到 **1 段/0.1641**。两者的断头仍分别
保留 17 与 7 处。
这两个配置的交叉**大量共点**（n5 CA 上 `X0002/X0003/X0011` 在同一点，全部 11 处交叉共点），引擎
已经分别报 `REGION-COINCIDENT-CROSSINGS`（boolean：各交叉各自扣除的重叠区互相抵消，该方法在这
种退化配置下无法保证面积）与 `REGION-LENS-APPROXIMATION`（arrangement），另有 `GEOM-NEAR_TANGENT`
与 `TOPOLOGY-ALTERNATION-RELAXED`。同一处 arrangement 后端画得完整。属"表示层把一次交叉的四个
角点归拢到一起"才能根治的那类问题，本轮不碰。

**测试**：`test_the_weave_notch_is_stroked_even_where_it_is_its_own_band_edge`（合成：共享边是
缺口必须描；被后画区域两面盖住必须隐藏）与
`test_the_boolean_backend_strokes_every_self_crossing_notch_whole`（`n = 7` CA：每个自交的缺口边
逐点检查"附近有同向描边且该处两侧可见归属不同"）。两条都实测会在旧顺序下失败。
全量 `pytest -q` → 390 passed，`ruff check` 干净，画廊 25 张卡全部重渲。

## 10. 第四轮：用户指出 CA7 卡左侧的"V"与"X"——描边断在丝带中间

**现象**（用户 crop 的 boolean 面板，左侧两处）：一处像一个"V"（楔形里两根线），一处像一个"X"
（两根线在丝带内相交）。定位方法：扫描**每一个描边端点**，判断它是否（a）与另一条描边共点、
（b）落在另一条描边上（T 形接头）、（c）落在丝带外轮廓上；三者都不是就是**断头**——线在填充
内部凭空结束。结果：`n = 7` CA boolean 有 6 处断头（含用户指的两处），arrangement 0 处。

**根因**：boolean 后端用 `_self_crossing_lens` 得到的**被分段窗口裁剪过的透镜**去切下股丝带。
那个透镜比"两条臂带求交"的真实重叠小（它的边界里还混着分段帽），所以切完之后**剩下的材料伸到
切口之外**——环上因此没有沿缺口末端的边，描边接不上，断在丝带中间。第三轮把 weave 记录换成
真实透镜后，这个缺口末端在 over 侧区域的环上被标成该描了，但**切口本身仍用被裁剪的那个**，
于是 under 侧的边到不了那里、over 侧的边又只是自己的带边，最终仍有一截没人画。

**修法**：切口也改用**两条臂带求交的真实重叠**，再与**上股的可见材料**求交——后者保留原代码的
不变式"切口绝不会开出一个上股没盖住的洞"（`_self_crossing_lens` 的 docstring 原话）。实测：
`n = 7` CA 的断头 6 → 0；`n = 10` PA level 1+2 前后都是 0（它那两处"断头"其实距另一条描边
3e-6，视觉上相连）。

**度量本身也修了一处 bug**：`benchmarks/weave_audit.py` 新增的 `dangling` 栏起初什么也测不出来
——每个端点都会匹配到**自己那条线**（距离恒为 0）而被判成"已连接"；它用的点查询又是 bbox 判定，
离 3e-6 的线根本不在返回集里。改成排除自己的线 + 用带缓冲的点查询后，它才能在旧切口上报出 6 处。
（这正是"先让度量能看见 bug"的价值：前一轮的判定顺序修复是同一个教训。）

**测试**：`test_the_boolean_backend_leaves_no_stroke_end_inside_the_ribbon`（参数化两张卡：
原卡与报告卡），判据直接复用 `benchmarks/weave_audit.py::dangling_ends`，实测在旧切口状态下
失败并列出 6 处（正含用户指出的两处）。

**残留（诚实降级，与 §9 同一批）**：`n5 CA L2 o12` 与 `n5 PO L2 o12` 仍有少量缺口或断头；
二者交叉大量共点、引擎分别报 `REGION-COINCIDENT-CROSSINGS` 与
`REGION-LENS-APPROXIMATION`。显式边界层已消掉大部分可见缺口，普通配置仍全部为四项
（缺陷/漏轮廓/缺口/断头）0。
