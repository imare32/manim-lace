## 0. 文档说明

本文将用户目标转化为可实现、可测试的产品需求。文档区分三种内容：

- **需求（MUST / SHOULD / MAY）**：项目应当提供或遵循的能力。
- **建议设计**：推荐的架构与算法路线，可以在原型验证后调整。
- **待决策项**：当前信息不足以冻结，需要在实现过程中用样例和测试确定。

本文的最高优先级是二维矢量路径的编织图案生成。编织过程动画是重要的增强能力，且应尽量体现真实算法步骤；美学系统也应预留扩展点，但完整的艺术指导、风格库和自动配色策略不属于第一阶段的核心验收范围。

## 1. 项目概述

### 1.1 项目愿景

构建一个面向 Manim Community Edition 的 Python 库，将任意受支持的 Manim 二维矢量路径转换为具有可控“交错编织”关系的蕾丝／带状图案；同时能够可选地把生成过程转化为 Manim 动画，让观众看到路径如何被识别、交点如何产生、上下穿插关系如何求解，以及丝带边界、切口、孔洞和最终片段如何逐步构成。

项目不是单一视觉滤镜，而是一个几何与拓扑驱动的图案生成引擎。核心结果应当可复现、可验证、可被程序访问，并能用不同的渲染方式呈现。

### 1.2 核心目标

1. **输入覆盖面广**：支持 Manim 的二维矢量对象、复合对象、多个子路径，以及由数学关系构造并最终表示为矢量路径的曲线。
2. **交叉识别可靠**：识别路径之间与路径自身的有效横穿交叉，并区分相切、端点接触、重合线段、多线共点等特殊情况。
3. **交错关系明确**：每个可处理的交叉都有明确的“谁在上、谁在下”状态；既支持自动规则，也支持用户指定。
4. **图案几何合理**：生成连续、可渲染的丝带区域，正确表现交叉处的遮挡、切口、边界和必要的孔洞。
5. **动画可解释**：动画步骤尽可能由算法阶段和真实几何数据驱动，不只是对最终图形套用通用的渐显效果。
6. **Manim 友好**：输出可作为 Manim `Mobject` / `VGroup` 使用，可参与场景动画、变换和组合。
7. **可诊断、可测试**：对不适定输入、冲突约束、采样不足、无效边界和退化情况提供明确诊断。

### 1.3 非目标（明确不做）

- 三维空间中的编织、真实深度相交或三维曲面织物模拟。
- 从位图照片自动识别路径；`ImageMobject` 不是天然矢量路径。如未来要支持，需单独的矢量化模块。
- 完整物理布料模拟、弹性形变、真实纤维材质或光线追踪。
- 第一版就保证对任何数学函数、任意精度、任意退化几何都能无条件生成唯一结果。
- 第一阶段就提供大量经过艺术设计的风格主题、自动艺术指导和复杂材质库。

### 1.4 基本成功定义

给定支持范围内的二维矢量输入，库应能将它们规范化为有序路径，识别有效交叉，产生可解释的过／欠关系，并输出稳定的编织图案。改变输入对象的内部采样密度、对象的遍历顺序或一次无意义的坐标平移，不应无故改变交叉拓扑。若输入存在无法唯一解释的退化情况，库必须显式告知或使用可配置策略，不能悄悄输出看似成功但拓扑错误的图案。

## 2. 范围与术语

### 2.1 “任意 Manim 二维矢量路径”的定义

“任意”表示输入来源和曲线形态具有广泛覆盖，而不是保证所有病态输入都有唯一的编织解。项目的核心对象是位于同一二维平面内的矢量路径及其组合。

输入可来自：

- Manim 基本几何对象，如 `Line`、`DashedLine`（需要定义虚线语义）、`Arc`、`Circle`、`Ellipse`、`Polygon`、`RegularPolygon`、`Star` 等。
- 自定义 `VMobject`、通过点和贝塞尔控制柄构造的路径、由多个贝塞尔段拼接而成的路径。
- `FunctionGraph` 等显式函数图像。
- `ParametricFunction` 等参数方程曲线，包括自交曲线、闭合曲线与周期曲线。
- `ImplicitFunction` 等隐式曲线对象，其几何可能包含多个分支或多个连通分量。
- `Text`、`MathTex`、`SVGMobject` 等具有矢量轮廓的对象，以及 `VGroup` 等复合对象。
- 经平移、旋转、缩放、拉伸等变换后的二维矢量对象。
- 由若干独立路径构成的路径网络。

输入不自动包括：位图图像、无法提取几何点的普通 `Mobject`、文字的语义笔画中心线（默认提取的是轮廓路径），以及未被投影或明确压平到 XY 平面的三维形状。

### 2.2 关键术语

- **源对象（Source Mobject）**：用户交给库的 Manim 对象或对象组。
- **源子路径（Source Subpath）**：从一个矢量对象提取到的一条独立路径。
- **规范化路径（Normalized Path）**：完成坐标整理、采样、退化检查后供几何内核使用的二维有序路径。
- **路径身份（Path ID）**：稳定标识一条规范化路径，供交叉、动画和诊断追踪。
- **交叉事件（Crossing Event）**：两次路径经过在二维平面中的一个有效横穿交点。自交时两次经过属于同一路径上的不同参数位置。
- **经过记录（Pass）**：某条路径在某个交叉事件处的一次通过，至少包括路径 ID、路径参数或弧长位置、切向与交叉 ID。
- **上下关系（Over/Under Assignment）**：某次交叉中哪一方视觉上位于上层、哪一方被压在下层。
- **编织拓扑（Weave Topology）**：交叉事件、各路径上的经过顺序、上下关系、断口范围及其约束的集合。
- **丝带边界（Ribbon Rails）**：中心线两侧形成的边缘曲线。
- **丝带片段（Ribbon Piece）**：在交叉处经过切分或区域构造后，可以独立渲染的丝带区域。
- **孔洞（Hole）**：编织轮廓中需要保留为空白或按背景／孔洞样式渲染的区域。
- **算法轨迹（Algorithm Trace）**：算法执行过程中可被记录和重放的结构化步骤，例如采样细分、确认交叉、约束传播、边界构造和面遍历。
- **视觉动画（Presentation Animation）**：对算法轨迹进行时间编排、强调、着色、镜头或标签呈现的动画层。

### 2.3 二维约束

- 几何内核以 XY 坐标计算。
- 若输入坐标带 Z 分量，应通过配置选择：接受 `z≈常数` 的平面路径并投影到 XY；或者在超过平面容差时发出警告／报错。
- 不解释路径在三维中的深度。所有上下关系均指二维绘制层级。

## 3. 用户与主要使用场景

### 3.1 目标用户

- 使用 Manim 制作数学动画的开发者与创作者。
- 需要将函数图像、参数曲线或矢量轮廓变为编织图案的用户。
- 希望教学展示交点、拓扑关系、区域分割与路径偏移过程的数学教育创作者。
- 希望以程序控制颜色、宽度、交叉顺序和动画节奏的视觉艺术开发者。

### 3.2 典型场景

1. 将两条或多条曲线转成相互交错的丝带。
2. 将单条自交参数曲线转成自我交错的编织图案。
3. 将圆、星形、多边形、玫瑰线、Lissajous 曲线或复杂贝塞尔路径生成蕾丝纹样。
4. 将 SVG 或文字轮廓中的多条路径组成图案；用户明确决定哪些轮廓作为编织路径。
5. 逐步展示输入路径、采样折线、交叉事件、过／欠关系、丝带边界、切口／孔洞与最终图案。
6. 教学展示算法失败案例，如相切、重合线段、交叉约束冲突，并动画呈现检测结果。

## 4. 功能需求

### 4.1 输入与路径提取

**FR-001：接受 Manim 矢量对象。** 主要入口应接受单个有路径的 `VMobject`，并支持对 `VGroup`／复合矢量对象进行递归提取。没有可用几何点的对象应返回可理解的错误，而不是静默生成空图案。

**FR-002：避免重复递归提取。** 遍历复合对象时不得把父对象和其子对象的同一批点重复收集。

**FR-003：保留源信息。** 每条提取路径必须保留源对象标识、源子路径序号、原始方向、闭合状态及其坐标／参数映射。此信息要能用于诊断、着色分组和动画标注。

**FR-004：识别贝塞尔结构。** 对标准三次贝塞尔数据应依据实际贝塞尔曲线采样，而非把控制柄误作曲线上经过的顶点。对未知或非标准点结构，须使用显式适配器、合理回退策略或报错，不得静默误解释点结构。

**FR-005：支持数学曲线入口。** 除从已有 `FunctionGraph`、`ParametricFunction`、`ImplicitFunction` 对象提取外，项目 MAY 提供直接从函数／方程生成规范化路径的工厂方法。直接入口必须显式接受定义域、范围、断点和采样误差等必要参数。

**FR-006：支持显式函数。** 对 `y=f(x)`，应支持指定 x 范围、采样误差、最大参数步长与已知断点。对非有限值、渐近线和检测到的不连续区间，应拆分路径，不得跨越断点强行连线。

**FR-007：支持参数曲线。** 对 `γ(t)=(x(t), y(t))`，应支持参数范围、周期闭合提示、采样误差、最大参数步长及已知断点；保留 t 与离散路径位置之间的映射，以支持交叉事件定位。

**FR-008：支持隐式曲线。** 通过现有 Manim 矢量对象或独立等值线提取器支持 `F(x,y)=0`。当结果包含多个连通分支时，应拆分为多条路径，并明确记录分支来源。隐式曲线的路径方向如不能由方程唯一决定，应由稳定的规范化规则或用户配置确定。

**FR-009：支持闭合与开放路径。** 首尾相同或在容差内相同的路径应能规范化为闭合路径；开放路径不得因端点接近而默认自动闭合，除非用户启用端点合并规则。

**FR-010：路径合并需显式可控。** 默认保留提取到的子路径身份。路径合并应作为可配置预处理，且必须区分“几何端点相连”与“用户希望它们成为同一路径”两种语义。分叉节点不得被隐式合并成任意的线性路径顺序。

**FR-011：处理虚线和装饰对象。** 对 `DashedLine`、箭头、带装饰的路径对象，提供明确语义选项：把实际可见线段分别作为路径、把装饰忽略后提取底层路径，或对该对象类型提示用户使用专用适配器。不得默认把装饰尖端当普通中心线交叉处理。

### 4.2 采样与几何规范化

**FR-020：自适应采样。** 除快速路径外，曲线采样 SHOULD 以几何误差为准，而非只有固定的每段采样点数。至少考虑弦偏差、切向变化、最大参数步长与局部曲率趋势。

**FR-021：与带宽关联。** 采样误差允许依据丝带半宽 `offset` 缩放，以免几何离散误差与所需带宽处于同一量级。该关系应可配置且可测试。

**FR-022：保存参数映射。** 采样点应保留来源曲线参数或等价的稳定位置映射。后续交叉可回溯到源曲线参数，动画可以指向原始曲线上的对应位置。

**FR-023：清洗重复点。** 去除连续重复点与低于容差的短边，但不能错误消除真实尖角、微小环路或局部自交结构。

**FR-024：清理共线点需尺度合理。** 共线判断必须考虑方向夹角而非仅比较未经归一化的叉积；闭合路径首尾绕回处也要正确处理。

**FR-025：坐标尺度和容差。** 提供清晰的容差配置，包括位置容差、角度／平行容差、端点吸附容差和最小有效边长。文档应说明哪些参数使用世界坐标单位、哪些是无量纲值。

**FR-026：坐标与路径规范化可视化。** SHOULD 可以输出采样点、删除点、短边和闭合状态等诊断图层，便于排查输入质量。

### 4.3 交叉检测与事件身份

**FR-030：检测路径间交叉。** 支持同一路径不同非相邻区段的自交，以及不同路径之间的交叉。

**FR-031：稳定交叉身份。** 每个交叉事件必须具有独立 ID，并记录参与路径、各自参数／弧长位置、交点位置、局部切向、交叉角度和事件类型。交叉身份不得由偏移边上的临时交点数量推导。

**FR-032：区分事件类型。** 至少区分：有效横穿、相切／近切、端点接触、共线重叠、多线共点、数值不确定交叉。只有有效横穿默认进入普通过／欠分配流程。

**FR-033：正确处理自交。** 同一路径在交叉处的两次经过必须是两条不同的 `Pass` 记录，即使其路径 ID 相同、空间坐标相同。

**FR-034：近距离交叉不能误合并。** 交点去重不能只依据二维距离；至少应同时比较路径身份、各侧参数／弧长位置和交叉类型。两个近邻但不同的交叉必须保留。

**FR-035：候选加速。** 使用包围盒、空间网格、R-tree、BVH 或其他空间索引减少线段两两检测的候选数量。加速结构不得改变精确几何判定的语义。

**FR-036：交叉精化。** 对由曲线离散化产生的候选交叉，允许在来源曲线上局部细化交点参数，以提高位置精度并区分浅角相交与近切情况。

**FR-037：交叉列表可检查。** API 应提供按路径顺序排列的交叉事件列表，并能查询每条路径经过哪些交叉、交叉位于何处以及事件判定依据。

### 4.4 编织拓扑与过／欠关系

**FR-040：拓扑与渲染解耦。** 上下关系的求解必须独立于 `stroke` 或 `ribbon` 渲染方式。不同渲染器应消费同一个编织拓扑，不能各自重新推导交叉身份。

**FR-041：默认交替模式。** 提供“沿路径交替过／欠”的自动模式，作为传统编织图案的默认规则之一。

**FR-042：显式上下覆盖。** 用户必须能够按交叉 ID 或路径经过记录指定哪一方在上。用户指定的值应优先于自动模式，除非采用明确声明的冲突策略。

**FR-043：自由分配模式。** 支持不要求每条路径严格交替的上下关系，从而表达具有奇环冲突的交叉网络或用户艺术性安排。

**FR-044：冲突诊断。** 当交替约束无法同时满足时，必须返回冲突所在的交叉／路径约束及原因，而不是静默地退化为不符合规则的普通描边。

**FR-045：自动冲突策略。** MAY 提供策略：直接报错、保留用户手动指定并放宽部分自动约束、尝试最少修改的近似解，或生成明确标记为“非严格交替”的结果。默认策略应确定性且文档化。

**FR-046：稳定结果。** 在路径顺序或内部遍历次序不变且输入几何相同的情况下，自动分配应可复现。若结果依赖随机种子，必须把种子公开为配置。

### 4.5 丝带几何构造

**FR-050：统一带宽语义。** `offset` 默认表示丝带半宽；总宽度为 `2 * offset`。其他 API 不得把半宽和总宽度混为一谈。

**FR-051：中心线描边后端。** 提供轻量 `stroke` 渲染器：在中心线弧长位置切分片段，并通过绘制顺序或局部遮挡形成过／欠关系。必须清楚披露其不透明度、切口端部和浅角交叉方面的限制。

**FR-052：实体区域后端。** 提供 `ribbon` 渲染器，将丝带作为具有面积的二维区域构造，输出边界、片段及必要的孔洞。此后端应支持填充色、轮廓线和闭合区域。

**FR-053：偏移线构造。** 偏移算法应支持直线段与平滑曲线离散结果，提供 miter／bevel／round 等连接策略或可扩展接口，并具有最大 miter 限制。

**FR-054：区域分割。** 实体区域模式 SHOULD 依据平面嵌入的面结构／半边关系或经验证的二维几何布尔算法提取实际区域边界。不得仅依赖一般图的环路基就断言得到了全部真实平面面域。

**FR-055：自交偏移的诊断。** 如果偏移边界因高曲率、狭窄环路或较大带宽而自交或塌缩，应返回可诊断的问题；可以尝试受控修复，但不得无提示地丢失片段或孔洞。

**FR-056：切口范围。** 切口应根据带宽、交叉角度和配置策略确定，并对浅角进行保护。切口不得意外移除上方路径本应可见的核心区域。

**FR-057：轮廓连续性。** 每个输出区域必须满足渲染器需要的闭合／开口约定；闭合多边形不得出现自相交轮廓、狭缝描边或重复边造成的明显瑕疵，除非明确作为特殊填充结构使用。

**FR-058：孔洞语义。** 区分几何孔洞、被上层丝带遮挡造成的背景空隙以及源对象原有轮廓的内孔。不能只依据面积大小将最大环简单视为整体外边界。

**FR-059：结果可访问。** 输出对象应同时提供几何结果（点集／曲线／面边界）和 Manim 渲染对象，方便后续导出、动画和测试。

### 4.6 渲染与样式接口

**FR-060：Manim 对象输出。** 结果可作为 `VGroup` 或等价 Manim 对象加入场景、组合和变换；需要区分几何对象、孔洞对象、轮廓对象与诊断图层。

**FR-061：基础样式。** 支持统一／按路径／按片段／按孔洞分组设置填充色、描边色、描边宽度、透明度和 z-index／绘制顺序。

**FR-062：样式与几何分离。** 改色、透明度、线型和调色板变化不应重新计算交叉拓扑。改变带宽会影响几何，应触发相应的重新构造。

**FR-063：随机风格可复现。** 若提供随机调色板，应支持显式随机种子。

**FR-064：美学模块可扩展。** 应预留样式策略接口，例如 `StylePolicy` / `PalettePolicy` / `PieceOrderingPolicy`。第一阶段只提供基础参数和少量默认样式，不要求完成全面的自动艺术指导。

### 4.7 编织动画与算法解释

动画属于项目的增强能力，但必须在架构初期考虑，避免日后把生成流程重构成无法解释的黑盒。

**FR-070：动画为可选功能。** 用户可以只求解和渲染最终图案，也可以请求生成算法讲解动画。两者共享同一套几何与拓扑结果。

**FR-071：算法轨迹。** 核心阶段应生成结构化的算法轨迹事件，而不只是回调文本。每个事件至少包含事件类型、相关路径／交叉／片段 ID、数据引用、阶段顺序及简短说明。

**FR-072：真实过程可视化。** 支持将以下阶段映射为动画：

1. 原始路径出现；
2. 路径拆分、采样点和局部细分显现；
3. 候选交点被检查，确认的交叉事件被编号；
4. 按路径顺序列出交叉经过；
5. 展示上下关系约束的传播或手动指定结果；
6. 生成左右偏移边界；
7. 在交叉处显示切口范围与局部几何；
8. 展示平面区域分割、孔洞识别或丝带片段闭合；
9. 按路径行进顺序、片段顺序或区域遍历顺序绘制最终结果。

这些阶段可以按模式选择，不要求每个动画都展示所有技术细节。

**FR-073：动画来自真实中间数据。** 交叉标号、切口位置、片段轮廓、孔洞和约束传播动画必须使用算法实际生成的数据。不得通过视觉上类似的假交点或不对应最终结果的装饰线误导观众。

**FR-074：步骤式教学控制。** 至少支持按阶段生成动画；SHOULD 支持单步展示、跳过阶段、配置每阶段时长和是否显示辅助标注。若 Manim 的渲染工作流不适合运行时交互，至少应支持在代码中确定性拼装每个阶段的 `Animation`。

**FR-075：动画可复现。** 相同输入、配置和随机种子应产生相同的事件顺序与动画阶段。动画不得依赖不稳定的字典遍历顺序或偶然的空间索引返回次序。

**FR-076：动画模式。** 至少规划：

- `overview`：简洁展现路径逐步成为编织图案；
- `algorithm`：展示采样、交叉、约束和区域构造；
- `construction`：展示边界、切口、孔洞与丝带片段的几何生成；
- `custom`：用户按阶段组合自己的动画。

**FR-077：动画与算法耗时解耦。** 不能简单把 Python 求解耗时当作屏幕动画时间。应预先计算结果与轨迹，再按配置时间播放；对大型输入允许限制可视化事件数量或将多个低层事件聚合为一个阶段。

**FR-078：动画数据访问。** 用户可以访问算法轨迹或阶段对象，自定义颜色、标签、镜头、停顿、逐个交叉强调及片段出现顺序。

**FR-079：不支持事件的解释。** 如果某交叉被分类为相切、多线共点或存在拓扑冲突，教学动画 SHOULD 可以突出该事件并显示诊断原因，而非默默跳过。

### 4.8 诊断与异常策略

**FR-080：验证模式。** 至少提供 `ignore`、`warn`、`raise` 或等价策略；建议默认警告，严格模式用于测试和批处理。

**FR-081：结构化诊断。** 问题应具有稳定代码、严重级别、相关路径／事件 ID、位置、摘要与建议操作。中文和英文文本可以是展示层，逻辑判断不应依赖错误字符串。

**FR-082：不静默降级。** 若渲染器回退到完整描边、舍弃某个孔洞或使用近似交替结果，必须在返回对象及日志中记录。

**FR-083：失败输出策略。** 可选择：硬错误、不绘制问题局部、绘制可用片段并标记问题、或显式近似。默认行为必须确定且文档化。

**FR-084：调试图层。** SHOULD 可开关显示交点、交点 ID、路径 ID、局部切线、边界线、断口、区域面 ID、孔洞轮廓、冲突约束和几何无效区。

## 5. 建议的内部架构

### 5.1 分层原则

建议采用以下模块边界。它们是实现建议，而不是强制使用特定第三方库。

1. **Input Adapters**：从 Manim 对象、显式函数、参数曲线、隐式曲线等构建规范化路径。
2. **Path Model**：保存路径点、闭合状态、来源对象、曲线参数映射与容差。
3. **Geometry Kernel**：负责距离、切向、包围盒、线段求交、曲线交叉细化及几何谓词。
4. **Crossing Detector**：输出具备稳定身份的 `CrossingEvent` 和 `Pass`。
5. **Weave Solver**：计算上下关系、交替规则与冲突诊断。
6. **Region / Ribbon Builder**：生成中心线切片、偏移边界、局部交叉区域、片段和孔洞。
7. **Topology Validator**：检查事件一致性、片段闭合、区域有效性和遮挡关系。
8. **Renderers**：`StrokeRenderer` 与 `RibbonRenderer` 负责把几何结果变成 Manim 对象。
9. **Trace Recorder**：记录采样、交叉、约束、边界和区域构造阶段的结构化事件。
10. **Animation Composer**：把算法轨迹映射到 Manim 的动画序列。
11. **Style Policy**：提供颜色、片段排序和基础美学策略，未来可独立扩展。

### 5.2 核心数据对象（建议）

**`PathSource`**：源对象 ID、对象类型、子路径索引、来源参数范围、闭合状态、原始方向、坐标变换和元数据。

**`PolylinePath`**：稳定路径 ID、有序采样点、闭合状态、累计弧长、采样误差估计、来源参数映射。

**`CrossingEvent`**：交叉 ID、事件类型、位置、参与路径 ID、各侧参数／弧长、各侧切向、交叉角度、置信／精度信息。

**`Pass`**：交叉 ID、路径 ID、经过序号、路径参数／弧长、在上下关系中的角色。

**`WeaveAssignment`**：交叉 ID、上方经过、下方经过、决定来源（自动／用户／近似）、约束说明。

**`RibbonPiece`**：片段 ID、来源路径 ID、参数／弧长区间、边界轮廓、邻接片段、相关交叉 ID、区域有效性状态。

**`HoleRegion`**：孔洞 ID、轮廓、来源及其分类（几何内孔／编织空隙／其他）。

**`Diagnostic`**：代码、级别、消息、来源路径、交叉 ID、坐标、修复建议。

**`TraceEvent`**：阶段 ID、事件类型、相关对象 ID、数据引用、说明、可视化提示与顺序索引。

所有 ID 应在一次求解内稳定，并避免仅用浮点坐标作为唯一身份。

### 5.3 两种渲染后端的职责

**StrokeRenderer** 侧重效率和视觉效果：依据交叉事件在中心线上切出片段，使用描边宽度、断口范围与绘制顺序展示上下关系。它适合不透明二维图案，但必须说明在浅角、透明度、交叉密集及复杂遮挡环路中的限制。

**RibbonRenderer** 侧重区域几何：生成左右边界、围绕交叉形成的局部轮廓、闭合片段和孔洞。建议利用经过测试的二维面分割／布尔运算机制，而不是靠不稳定的环路启发式恢复所有面域。

两者必须共用同一个 `WeaveTopology`，而不是共享不完整的几何代码。

## 6. 数学与几何策略建议

### 6.1 不将偏移线交点作为交叉身份的来源

中心线交叉应首先被检测并分配 ID。偏移线会在交叉附近产生多个边界交点，这些点应该关联回既有事件，用于构造几何，而不能反过来决定交叉事件身份。

### 6.2 区分“路径交叉图”与“平面区域图”

路径／交叉图用于表达哪些路径在何处相交、上下关系有哪些约束；平面区域结构用于表达几何边界和实际面域。这是不同的数据模型。普通图的循环空间基不保证等于平面图的全部有界面，因此区域提取需要实际平面嵌入信息、半边结构或可靠的二维布尔运算。

### 6.3 交叉角度与断口

交叉角度应使用局部切向计算。切口可以基于带宽与交叉角估算初始范围，但最终范围应以局部区域构造和视觉／几何验证为准。浅角情况下不能只通过无上限地增大断口来处理；需要设定上限、近切分类和用户可配置策略。

### 6.4 偏移几何与局部曲率

当曲率半径接近或小于偏移距离时，偏移轮廓可能产生尖点、自交或塌缩。算法必须允许这类情况成为诊断结果；不能假设给定任何中心线与带宽都一定会形成拓扑简单的丝带。

### 6.5 容差体系

至少拆分为：

- 位置容差：点是否在几何意义上重合；
- 角度容差：是否视为平行／相切；
- 端点合并容差：端点是否可以吸附；
- 采样误差容差：离散路径对原曲线的近似误差；
- 最小边长／最小区域面积：退化几何阈值。

这些阈值应考虑模型尺度、`offset` 和局部边长；避免用同一个固定绝对值处理所有类型的判断。

## 7. API 草案

以下仅为接口方向示例，最终命名可以在原型阶段统一；不代表这些 API 已实现。

```python
from manim import *
from manim_lace import Lace

# 现有 Manim 矢量对象
lace = Lace(
    Circle(radius=2),
    offset=0.12,
    render="ribbon",
)

# 参数曲线入口
lace = Lace.from_parametric(
    func=lambda t: (np.cos(t), np.sin(3 * t)),
    t_range=(0, TAU),
    offset=0.12,
    sampling={"max_error": 0.002},
)

# 控制编织规则
lace = Lace(
    VGroup(curve_a, curve_b),
    offset=0.12,
    weave={"mode": "alternating"},
)

# 生成算法解释动画
plan = lace.build_animation(
    mode="algorithm",
    show_sampling=True,
    show_crossing_ids=True,
    show_constraints=True,
    show_region_construction=True,
)
self.play(plan.animation)
```

建议 API 具有以下职责：

- `Lace(...)`：从现成 Manim 对象构建结果。
- `Lace.from_graph(...)`：从显式函数构建。
- `Lace.from_parametric(...)`：从参数函数构建。
- `Lace.from_implicit(...)`：从隐式函数构建或调用等值线提取器。
- `lace.solve()`：运行或更新规范化、交叉与编织求解。
- `lace.topology`：访问交叉事件及上下关系。
- `lace.geometry`：访问边界、区域、片段和孔洞几何。
- `lace.diagnostics`：访问结构化诊断。
- `lace.trace`：访问算法轨迹。
- `lace.as_mobject()`：获得最终 Manim 对象。
- `lace.build_animation(...)`：依据计算结果与轨迹生成动画计划。

如输入对象或 `offset` 发生变化，应明确哪些缓存失效：位置变换通常会使几何坐标变化；仅改色不应重算拓扑；改变 `offset` 会使边界、切口和区域构造失效。

## 8. 编织动画需求详述

### 8.1 动画的产品定位

动画不是第一优先级的几何正确性的替代品，而是构建在可靠数据模型上的解释层。首要目标是让用户和观众看懂“图案如何被算出来”。在此基础上，才添加更具装饰性与节奏感的呈现方式。

### 8.2 建议动画剧本

**A. 轮廓到路径**：显示源对象；高亮每个子路径；显示采样点；必要时以放大框展示自适应细分，并说明弦误差或采样不足的原因。

**B. 从路径到交叉事件**：遍历路径段；突出候选段对；将确认的有效交叉打上编号；用不同符号标记被分类为相切、端点接触或重合的事件。

**C. 从交叉到拓扑**：沿路径方向显示每次交叉经过的顺序；显示默认交替约束或用户给定约束；以图节点／边或者文字标签说明某个上下关系为什么被赋值；冲突时高亮导致冲突的约束环。

**D. 从中心线到丝带**：逐步生成左右偏移边界；在交叉处显示局部切线与交叉角；展现断口范围或局部拼接区域的形成过程。

**E. 从区域到成品**：逐面高亮区域遍历；逐步填充孔洞背景或保留内孔；按源路径顺序、片段顺序或拓扑顺序显示丝带片段；最后统一呈现完整图案。

### 8.3 动画模式与时间配置

- `overview`：适合一般观众，隐藏低层算法细节。
- `algorithm`：适合数学／算法讲解，突出事件、约束和面结构。
- `construction`：突出几何边界、切口、区域闭合与孔洞生成。
- `debug`：显示路径／交叉 ID、误差、退化事件、边界无效区域等详细信息。
- `custom`：用户选择阶段并控制顺序。

时间系统至少支持每个阶段的时长、缓动方式、停顿、是否显示标签、是否显示辅助几何。动画应基于确定性阶段计划，避免把算法运行耗时直接转换成动画时长。

### 8.4 动画验收原则

1. 动画显示的交叉位置与最终几何一致。
2. 上下关系标记与最终遮挡结果一致。
3. 显示出来的偏移线、切口与孔洞应是实际算法结果或明确标为示意的辅助层。
4. 关闭动画后仍可直接获得同样的最终图案。
5. 任何被跳过或近似处理的事件，应在 debug 模式或诊断中可查。

## 9. 美学与视觉设计需求（预留，不作为第一阶段深度研究）

美学设计和几何算法分开。几何引擎决定“哪些区域存在、谁遮挡谁、边界在哪里”；样式策略决定“用什么颜色、线宽、对比度、出现节奏和视觉层级呈现”。

第一阶段建议提供：

- 稳定、可复现的基础配色；
- 按源路径或丝带片段分色；
- 孔洞填色／透明背景两种基本策略；
- 边框宽度、边框颜色、填充透明度；
- 最终图案的总体绘制顺序；
- 动画阶段的辅助色与强调色。

后续可独立研究：

- 蕾丝、凯尔特结、绳结、编带等不同视觉语法；
- 颜色和片段分组的美学策略；
- 断口端部的圆角、覆盖余量与抗锯齿观感；
- 密集交叉区域的视觉简化；
- 留白、背景和图案对称性；
- 按路径长度、拓扑角色或空间区域进行层次分色；
- 片段生成与最终展示时的节奏设计。

不应让美学策略偷偷改变拓扑；若某种风格确实需要改变几何（例如圆角切口、局部扩宽、缩短片段），应由明确的几何风格参数完成，并进行验证。

## 10. 非功能需求

### 10.1 正确性与确定性

- 相同输入、参数和种子应生成相同的路径身份、交叉事件及上下关系。
- 对有效的横穿交叉，每个事件必须恰好有两次经过，且最终分配必须一上一下。
- 对明确标记为无法唯一解释的退化事件，不强行给出未经说明的唯一解。
- 几何输出应通过闭合、非退化、区域面积和边界自交等检查。

### 10.2 性能

- 大多数无交叉的长路径不应触发全量昂贵的局部构造。
- 使用包围盒和空间索引进行候选筛选；精确检测只在候选对上运行。
- 采样与区域构造应可单独计时和分析。
- 提供可重复的性能基准集，至少覆盖简单图形、密采样平滑曲线、大量自交曲线和多路径网络。
- 性能目标在基准输入集确定后冻结；优化不得破坏拓扑结果。

### 10.3 可测试性

- 几何内核不依赖 Manim 渲染后端，能以纯数值对象独立测试。
- 交叉求解、约束求解、区域构造、动画轨迹记录分别有单元测试。
- 建立固定的黄金样例和可视回归样例。
- 对随机测试固定 seed；失败用例应能序列化并复现。

### 10.4 可扩展性

- 新输入适配器无需重写编织拓扑模块。
- 新渲染器可以消费同一拓扑结果。
- 新动画模式可以消费已有 TraceEvent，不应把逻辑写进几何求解器。
- 样式策略可以扩展而不改变几何正确性。

### 10.5 兼容性与依赖

- 明确支持的 Python 与 Manim Community 版本，并在 CI 中固定版本测试。
- 对 Manim 内部点结构的依赖应集中在适配层，避免散落在核心算法中。
- 若依赖 NumPy、SciPy、NetworkX 或二维几何库，应在包元数据中明确声明依赖与版本范围。
- 优先避免让核心几何算法依赖渲染器的像素输出或屏幕分辨率。

### 10.6 文档与可用性

- 每个公开参数说明单位、默认值、作用范围与对缓存的影响。
- 为常见输入提供最小示例：圆、多边形、参数曲线、自交曲线、多个路径、SVG／文字轮廓。
- 说明不支持情况、诊断代码和修复建议。
- 为算法动画提供“从简单图案开始”的教学例程。

## 13. 风险与应对

**风险 A：固定采样遗漏交叉或细节。** 采用自适应采样、已知断点提示、局部精化；对无法保证的黑盒函数明确说明限制。

**风险 B：交点坐标去重误合并事件。** 使用路径身份、参数位置、切向和事件类型共同判定，不仅依赖空间距离。

**风险 C：严格交替约束无解。** 分离自动交替与自由分配，提供结构化冲突报告及确定性的降级策略。

**风险 D：偏移线在高曲率处自交。** 检查带宽与局部曲率关系，采用局部修复或显式诊断，不把区域塌缩当作普通情况。

**风险 E：从一般图的环路误判真实孔洞。** 区域模式使用平面嵌入、面遍历／半边结构或经验证的布尔算法。

**风险 F：动画与实际算法脱节。** 从真实数据结构生成 TraceEvent，动画层只消费轨迹，不自行猜测交点与轮廓。

**风险 G：输入对象语义不明确。** 允许输入适配器和语义选项；对文字轮廓、虚线、箭头、复合路径提供说明，不把所有 Mobject 一概当作相同类型。

## 14. 待决策项

以下项目适合用一组小型基准例程做实验后决定，不宜在缺少验证时过早冻结：

1. 实体区域模式使用自研 half-edge／planar arrangement，还是引入成熟二维几何布尔库，或者采用组合方案。
2. 自适应采样默认误差与 `offset` 的建议比例，以及最大深度和最小步长。
3. 自动上下关系在奇环冲突时，默认采取报错、放宽交替还是最小修改策略。
4. 用户对输入 `VGroup` 的默认语义：每个子路径独立、按端点相连合并，还是完全由选项决定。建议默认独立保留。
5. `Text`／`MathTex`／SVG 默认把轮廓当中心线，还是要求用户显式确认。建议给出警告或提供清晰的 `source_mode` 选择。
6. 默认输出是实体区域 `ribbon` 还是轻量 `stroke`。建议 API 首期允许显式选择，不把视觉近似包装成几何等价。
7. 动画 API 的最终形式：直接返回 `AnimationGroup`、返回有阶段索引的 `AnimationPlan`，还是同时提供二者。
8. 面向教学的动画是否需要提供中间图模型可视化（交叉约束图、平面面域图），还是先以几何覆盖层为主。

## 15. 最终产品原则

1. **路径表示优先统一**：不同 Manim 对象和数学输入最终映射到同一套可追踪的规范化二维路径。
2. **交叉事件是拓扑基础**：交叉身份来自中心线／规范化路径，而不是从偏移边上反向猜测。
3. **拓扑与区域几何分离**：先解决谁与谁相交、谁在上；再解决丝带边界、切口与孔洞如何构造。
4. **渲染后端共享拓扑**：Stroke 与实体 Ribbon 可以不同，但上下关系不能各自得出不同答案。
5. **真实算法驱动动画**：动画讲解数据必须对应实际执行结果。
6. **美学可扩展但不可篡改拓扑**：视觉风格是独立策略，几何变化必须显式声明。
7. **失败要可解释**：不支持的退化输入必须被识别、记录，并按明确策略处理。
8. **用测试定义“任意”**：支持范围通过输入类别、测试矩阵、确定性与诊断契约逐步扩展，而不是靠口号保证。

**本文建议作为项目 1.0 的需求基线。** 后续架构设计应优先冻结数据模型与行为契约，再选择具体几何库和渲染实现；这样既能较早获得可用的 Stroke 版本，也不会阻碍后续实体丝带、孔洞构造和算法解释动画的发展。
